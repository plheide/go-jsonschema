# About this fork

`plheide/go-jsonschema` is a fork of [`omissis/go-jsonschema`](https://github.com/omissis/go-jsonschema). It
exists so that work offered upstream can be used before upstream has reviewed it. It is a staging area, not a
competitor: once upstream merges a change, the fork takes that change from upstream.

## What it carries

The generator changes are offered upstream as
[pull requests](https://github.com/omissis/go-jsonschema/pulls?q=is%3Apr+author%3Aplheide). Each one is a branch
in a stack, from `feat/p0i-quote-property-names` to `feat/p14-stable-decl-order`. Each layer of the stack was
reviewed and merged into this fork's `main` on its own.

Not offered upstream yet:

* `--version`, which reports the stamps the release build sets (`feat/p15-version`);
* keeping a property literally named `-` as a JSON key (`feat/p16-dash-json-key`);
* everything fork-specific: release and image publishing, the module path, the README banner and this file.

## Branches

* `main` is the fork's product and its source line. It changes only through reviewed pull requests, and
  releases are tagged from it.
* `upstream-main` mirrors upstream's `main` and is only ever fast-forwarded. The `feat/*` stack is based on it.
* `feat/*` is the stack whose branches head the upstream pull requests. A change there changes an upstream pull
  request, so these branches change only to follow review.

## Module path

The fork's module path is `github.com/plheide/go-jsonschema`, so
`go install github.com/plheide/go-jsonschema@latest` installs it. Generated files keep upstream's
`Code generated by github.com/atombender/go-jsonschema` header, so the new module path doesn't change it. The one
difference it makes: output for `format: date` or `format: time` imports `pkg/types` from
`github.com/plheide/go-jsonschema`, so that code depends on the fork.

## Following upstream

`scripts/fork/sync-upstream.sh` fast-forwards `upstream-main` from upstream, and `main` takes it in through a pull
request. A change exported upstream from `main` is cherry-picked onto a branch based on `upstream-main`, and
`scripts/fork/rewrite-module-path.sh --reverse` rewrites the module path back to
`github.com/atombender/go-jsonschema`.

## Scripts

In `scripts/fork/`:

* `sync-upstream.sh [--dry-run]` fast-forwards `upstream-main`, locally and on the fork.
* `rewrite-module-path.sh [--reverse]` switches the module path between upstream's and the fork's. fork-guard runs
  it on every change to `main` and fails if it finds anything left to rewrite.
* `merge-layer.sh <pr>` merges a pull request into `main` only if it targets `main`, GitHub reports it clean, its
  head matches your local branch, and the repository doesn't delete head branches on merge.
* `install-hooks.sh` installs a `pre-push` guard that refuses pushing `main`, deleting a `feat/*` branch, and
  pushing a tag whose `go.mod` doesn't declare the fork's module path.
